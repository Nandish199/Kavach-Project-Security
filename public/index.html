Audit method

Kavach adapts the source-first principles of Cloudflare’s security audit skill for a single-device workspace, with local models and signed-in CLI choices.

Cloudflare security audit, six phasesPhases6

  1. Reconnaissance

    Four fresh model passes map the product and stack, principals and trust boundaries, source entry points and sinks, and safe local-check options. Kavach loads prior same-source ledgers from PostgreSQL, compares per-file hashes, selects matching Cloudflare companion guidance, and creates the coverage plan.

    Source map

  2. Coverage-led hunting

    Reviewers work through the source-derived surface × boundary × subsystem × attack-class ledger. A post-wave critic finds omissions and reassigns work. Standard and Deep repeat waves until a distinct final-clean critic accepts coverage or the call budget is reached; Quick uses one wave and its final critic.

    Coverage loop

  3. Validate each candidate

    A fresh reviewer re-reads each candidate and tries to disprove the trace. When Docker is enabled, Kavach may run up to eight small, candidate-specific Node checks against a read-only copy of the scanned files. Confirmation requires a completed result that supports the exact claim.

    Refutation

  4. Validate structured records

    Kavach validates findings against Cloudflare’s vendored report schema and runs the official findings and coverage-ledger validators after ledger or record changes. Invalid records stay unresolved in the report.

    Schema check

  5. Independently verify records

    Standard and Deep use a separate fresh reviewer for every retained candidate. Quick combines this check with candidate validation using the same verifier, as Cloudflare specifies. A material replacement in Standard or Deep requires another fresh review and schema validation.

    Final review

  6. Write and package the report

    The selected model provider writes the target-neutral posture and coverage summary from validated facts. Kavach creates the architecture map, exact coverage ledger, findings, confirmed details and needs-validation handoff for Markdown, PDF print, SARIF, or ZIP download.

    Report files

Workflow fidelity and evidence limits. Kavach implements all six phases and vendors the Cloudflare skill and its validators. Reviewer roles are fresh, stateless prompts to the selected model provider, not separate delegated model agents. Hosted providers receive selected source excerpts for processing. Candidate probes run only when Docker is enabled and available; they support self-contained Node.js checks and do not install dependencies, build the project, or contact services. The parent retains bounded, redacted output after each container exits. The official skill’s per-agent scratch-directory handoff is not implemented. Source-only and unresolved candidates remain needs validation, and a complete workflow is not a safety certificate.
